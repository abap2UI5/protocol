# Backend conformance suite

Plays the frontend: drives a backend over HTTP through the
[conformance apps](../apps/README.md) and checks the protocol behaviour the
specification ([../../spec/](../../spec/README.md)) requires of a backend.
Every 2xx response is also validated against
[`schema/response.schema.json`](../../schema/response.schema.json), every
request the suite sends against
[`schema/request.schema.json`](../../schema/request.schema.json).

Node 22 or later; no runtime dependencies.

## Run it

```bash
# against any backend that serves the conformance apps
npx abap2ui5-conformance backend --url https://host/sap/bc/z2ui5 --profile ui5 \
    --header "Authorization: Basic $(printf '%s' 'user:pass' | base64)"

# against the two reference backends, from this repository
npm run conformance:node-runtime     # @abap2ui5/node-runtime + the ABAP apps
npm run conformance:cap2ui5          # cap2UI5 + the JS apps (npm ci --prefix conformance/hosts/cap2ui5 first)
```

| Option | |
|---|---|
| `--url <endpoint>` | the roundtrip endpoint - the URL the page is served from |
| `--profile core\|ui5` | `core` (default): the core protocol; `ui5`: plus the UI5 profile (the page, view roots, binding paths, wire forms) |
| `--header "Name: value"` | an extra header on every request (repeatable) - authentication |
| `--only <id part>` | run only checks whose id contains it (repeatable) |
| `--app KEY=CLASS` | another class name for a conformance app (`ECHO`, `BIND`, `MSG`, `SLOTS`, `NAV`, `NAV_TGT`, `ROUTE`, `ERROR`, `ACTIONS`) |
| `--json` | the report as JSON |
| `--verbose` | the reasons of skipped checks and the last exchanges of every failure |

Exit code 0: no MUST check failed (the backend conforms to the profile).
1: at least one did. 2: a usage error.

A **MUST** check that fails is a `FAIL`; a **SHOULD** check that fails is a
`WARN` and does not affect conformance. Every check starts fresh (its own
app starts), so checks are independent and can run in any order.

Against an ABAP system: pull [`../apps/abap/`](../apps/abap/) with abapGit,
then point `--url` at the abap2UI5 ICF node. The CSRF check sends a foreign
`Origin`; a system that switched the gate off reports a warning there.

## As a library

```js
import { runBackendSuite, formatSummary } from "@abap2ui5/protocol";

const report = await runBackendSuite({
  url: "http://localhost:3000/",
  profile: "ui5",                 // or "core"
  headers: {},                    // authentication
  apps: {},                       // { ECHO: "ZMY_ECHO", ... }
  onResult: (r) => console.log(r.status, r.id),
});
console.log(formatSummary(report), report.ok);
```

`report.results[]` is `{ id, title, level, profile, spec, status, message,
ms, roundtrips }`; `status` is `pass`, `fail`, `warn` or `skip`. The package
also exports the client (`ProtocolClient`), the response readers
(`displays`, `routerOptions`, ...), the schema validator (`validate(name,
value)`) and `ALL_CHECKS`.

## Writing a check

A check is an object in `lib/checks/<area>.mjs`: `id` (`<area>.<name>`),
`title`, `level` (`MUST`/`SHOULD`), `profile` (`core`/`ui5`), `spec` (the
section it tests - `npm test` resolves the anchor) and `async run(t)`. `t`
carries the `client` (one per check), the app names (`t.apps`), and
assertions (`ok`, `equal`, `deepEqual` - key order insensitive - `fail`,
`skip`, `roundtrip`, `start`, `event`). Add the check id to the spec's
*Checked by* line, regenerate the list above, record the traffic again
(`npm run record`).
